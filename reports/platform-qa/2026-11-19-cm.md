### 2. Two failed reads at sign-in on a new device wipe the trainee's notes, Net Sheet, filing and Case Flow work  — high
Where: `index.html:3271-3274` (`cloudRestore` uses `sharedGet`, which turns any failure into "nothing saved"), `:3256-3269`
(`cloudSaveNow` then saves the device's copy), `js/cm-safe-logout.js:307` (one strict re-read, then it falls back to the same
`cloudRestore`); Worker `worker.js` `progress:` branch + `worker-identity.js:140-158` (`keepProgressAttempts` keeps only the KC
attempts)   Category: Bug (data loss)

What happens (plain): when a trainee signs in on a computer they haven't used before, the course downloads their saved work. If that
download fails twice in a row (a Worker 500 or a short network drop), the page carries on as if they had no saved work. Four seconds later
it saves the near-empty copy from the new computer over the real one. Their notes, Net Sheet, document filing, CMS log, Practice Lab work
and Case Flow module answers are gone. The page then says "☁ Progress saved to your account".

Verified (Playwright, repo's `server.mjs`):
1. Device A: trainee signs in, saves `notes`, `net-sheet`, `doc-filing`, and the cloud copy holds them.
2. Device B (empty browser): the first **two** `/api/storage/get` for `progress:<id>` return 500 (`cm-safe-logout`'s strict read and
   `cloudRestore`'s own). Sign in.
3. After 7 s, `progress:<id>` on the server: `notes`, `net-sheet`, `doc-filing`, `cms-log`, `lab-subs` are **gone**, and
   `state.saveStatus === "saved"`.
With one failure the safe-logout retry saves the day: that case was tested too, and nothing was lost. In secure mode the Worker keeps only
`day-progress` KC attempts on a progress write (`keepProgressAttempts`), so the same keys would be lost there too.

The `offline` status already says "⚠ Couldn't reach the server — saved on this device and will retry", which is true here. `restoreMerged`
and `cm-safe-logout` keep working: both call `cloudRestore`, and a real "no record yet" still returns `null` and clears the flag. Add a
browser check `.github/scripts/restore-fail.cjs` with the two-500 route above, and assert that the stored `notes` / `net-sheet` are
unchanged. `.github/scripts/requests.cjs` should still pass, because the retry runs only after a failure.

### 5. Knowledge Check scores and the trainer's 40% are whatever the trainee's browser says  — medium
