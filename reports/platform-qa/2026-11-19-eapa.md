### 1. Any Portal ticket opens EA / PA and makes the holder an approved trainee  — high
Where: `worker.js:204-217` (`readPortalTicket`), `:671-704` (`/api/auth/portal`); Portal `functions/api/launch.js:202` (tools skip the access check)   Category: Disconnect (SSO)

What happens (plain): the Portal now stamps every pass with the program it is for, but EA / PA never reads that stamp. It
accepts any pass the Portal signed, and then marks the person approved.

Steps:
1. Jane is approved on the Portal and has a batch, but has no EA / PA access. She never requested it, it is Pending, or she
   has another program only.
2. She opens `/api/launch?tool=kb`, or the program she does have. The Portal redirects her with `?ticket=…`, where `p` is
   `"kb"` or that program's topic key.
3. Within 5 minutes she opens `https://ea-pa-training.legalsupporthelp.workers.dev/?ticket=<same>`.
4. EA / PA signs her in and writes `trainee:jane-roe--b111926` with `approved: true`. Her progress, scores and certificate
   count from then on, and she appears in the EA roster and on the Portal's Trainee Monitoring.

Verified (probe): with `p: "kb"` the result was 200 and the record had `approved: true`. With `p: "LIEN NEGOTIATION"` the
result was also 200. Replaying the same ticket gave 200 again.

Why the Portal's block list doesn't stop it: `programBlock` blocks only records that already exist under `trainee:`.

### 3. A revoked trainee's EA / PA progress survives the Portal's purge, and comes back if the name and batch register again  — medium
Where: EA `worker.js:253-276` (progress lives in R2 under `eapa/progress:<id>`); Portal `functions/_purge.js:82,141-145,183-189` (it deletes KV keys only; the Portal has no R2 binding, `wrangler.toml`)   Category: Disconnect

What happens:
1. A trainer revokes Mo Diaz on the Portal (Users → Revoke & delete). The purge deletes `trainee:mo-diaz--b111926`,
   `progress:mo-diaz--b111926` and `backup:progress:…` from KV. The summary says his course records are gone.
2. His real progress copy is the R2 object `eapa/progress:mo-diaz--b111926`. KV holds only a once-a-day copy
   (`R2_KV_COPY_MS`). The Portal can't see R2, so the R2 object stays.
3. Someone registers again as Mo Diaz in B111926, or his account is restored. The first sign-in creates a new trainee record,
   and `cloudRestore` (`index.html:3768-3790`) reads the R2 copy and **restores the old progress**: days done, notes,
   submissions.

Verified (probe): save progress, delete the three KV keys exactly as the purge does, sign in again, and
`/api/storage/get progress:…` returns the old snapshot. This also means a revoked trainee's work is never actually erased,
although the Portal tells the admin it was.

Fix: proposed. It concerns deletion and what a trainee sees. The fix belongs on the EA side, because the Portal can't
reach the bucket. When `/api/auth/portal` creates a **brand-new** trainee record, any R2 progress under that id is left over
from a deleted record, so delete it:

```diff
+          // no trainee record under this id: an admin deleted it, or the Portal revoked the account. Progress left in R2 is theirs

           const rec = Object.assign({}, cur || { … }, { approved: true });
```
This does not touch `linkSameName`, which only links a record that exists and has progress. Add a case to `storage.mjs`.
The alternative is a `purged:<id>` tombstone that the Portal writes and EA checks, but that is a contract change in
`COURSE-PROGRAMS.md`.

## Verified working
- **SSO basics:** a wrong secret gets 401 `signature`, an expired ticket gets 401, a ticket with no batch is refused, a
  missing `PORTAL_SSO_SECRET` gets 503 `portal-secret-missing`, and a typed name + batch gets 403 `portal-required`. An admin
  ticket works once (`sso.cjs` passes). The ticket is removed from the address bar first (`js/portal-gate.js:24-29`).
- **`access:blocked`:** sign-in reads the list fresh (no 60-second window, unlike FT). A trainee token is refused on every
  request, except the read of their own record, which comes back shown as rejected so the page closes. Blocked trainees are
  dropped from every admin list. The key matches the Portal's (`prefix ''`).
- **Graded calls:** the Ring Channel → `/api/call-results` → `callsim:<id>` path (with `trainee-alias:`) → the dashboard card.
  A trainee reads only their own and can't write it (`graded-calls.cjs` passes).
- **Day count:** 10 days in the course, in `program-progress.js` and in `_attendance.js`, with `dayProgress` ids 1–10, so
  Trainee Monitoring's grid is right.
- **Registration:** EA / PA's topic key, id, label, prefix and URL are the same in `_programs.js`, `launch.js`, `programs.html`,
  `program-progress.js`, `_attendance.js` and `portal-nav.js` (two spaces everywhere).
