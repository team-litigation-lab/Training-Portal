Platform standards

The standing rules we work to across the LSH web platform. Every one of them is already implemented — this board is the collation; the detail lives in STANDARDS.md, README.md, SIMULATORS.md and CODEMAP.md.

01 · Sign-in & access

One sign-in, on the Portal

  • A name alone never signs anyone in.
  • SSO is an HMAC ticket — 5 minutes, used once; never a shared password.
  • A ticket never signs in an admin: they get the admin prompt.
  • Batch ID B + MMDDYY; a program keys a trainee on first, last and batch.
  • Gating is server-side; no heartbeat for 90 s ends the session.

02 · Simulators

The same shell, the same identity

  • Shell order: app.js, portal.js, sim.js, then its own.
  • Identity before first paint — Sim.ready.
  • A signed-in trainee always practices as their own account.
  • Scores come from the scorecard; the AI writes feedback, never the number.
  • Extend with a pack, don't add a simulator. Claim it first.

03 · Navigation

Every page gets back

  • Every page loads /portal-nav.js and shows "← Back".
  • Portal pages open in the same tab; only the courses open a new one.
  • Home links go to /index.html?stay=1.
  • One admin bar, one trainee bar — both from PortalNav.

04 · Page style

The portal look is the default

  • theme.css loads last on every page.
  • The backdrop is tuned only by the three --portal-* variables.
  • Glass panels use the background shorthand, never background-image.
  • AA contrast against the photo, not a white card. Orange is a fill.
  • IBM Plex Sans and Mono; navy #0f2148, orange #f97316.

05 · Request budget

Every LSH site shares one allowance

  • One /api/live every 20 s; 60 s in a background tab.
  • Heartbeat every 30 s.
  • Progress once a minute, only on a page that shows it, only in view.
  • Stay under KV's 1,000 operations per request.

06 · Data & secrets

Shared databases, shared care

  • A schema change stays backward compatible.
  • Course keys keep their prefixes — ft: cm: pd: md:.
  • Secrets live in Cloudflare only; a missing one says so plainly.
  • CSV exports quote against formula injection; files are typed by content.
  • Shared helpers live once, in _utils.js and util.js.

07 · Knowledge Base

Nothing is lost, nothing is unreviewed

  • Every save is a version; nothing is overwritten.
  • Every edit waits for approval; nobody approves their own.
  • Tenured VAs, reviewers and admins edit; Info Access reads.
  • Safe Markdown; titles in sentence case.
  • Sources are de-identified; credentials are never copied.

08 · CI & uptime

Red means broken

  • Checks run on every pull request and every push.
  • Everything parses, every local file exists, JSON is valid, Functions build.
  • The smoke test opens every page at desktop and phone width.
  • A new page goes in PAGES in smoke.cjs. CI never deploys.
  • Uptime sweeps at :07 and :37 and opens a site-down issue.

09 · Working practice

Validate, then push

  • Work the designated branch; no pull request unless one is asked for.
  • A red CI costs more than the finding was worth.
  • Keep each fix minimal; the docs change in the same commit.
  • Weekly inventory: every finding needs a file:line and a failure path.
